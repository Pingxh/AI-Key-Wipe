## 安全审查范围

对代码变更进行安全检查，重点关注以下方面：

### 1. API Key 处理
- 密钥匹配规则是否准确（过宽/过窄）
- 清理后是否残留部分密钥片段
- 日志中是否意外输出密钥内容

### 2. 文件操作安全
- 文件读写是否使用安全的临时文件策略
- 文件路径是否经过校验（防止路径遍历）
- 清理操作是否提供撤销/回滚机制

### 3. 数据泄露风险
- 错误消息中是否包含敏感路径或文件内容
- 调试/日志输出是否在生产构建中被禁用
- 剪贴板操作是否及时清除

### 4. Rust 安全实践
- 是否使用 `unsafe` 代码及其必要性
- 是否正确处理 `Result` 和 `Option`（无 unwrap 崩溃风险）
- 序列化/反序列化是否限制了类型

---

## 审查流程

1. 读取变更文件的差异（!`git diff HEAD~1`）
2. 对每个文件按上述范围逐项检查
3. 标记发现的问题（严重/警告/建议）
4. 对每个问题提供修复建议
